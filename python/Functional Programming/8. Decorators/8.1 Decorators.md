# Decorators
Remember function transformations, where a (higher-order) function takes a function and returns a function with new behaviour? Python decorators offer a kind of syntactic sugar around that. ("Syntactic sugar" just means "a more convenient syntax.")

Example:

```python
from collections.abc import Callable

def vowel_counter(func_to_decorate: Callable[[str], None]) -> Callable[[str], None]:
    vowel_count: int = 0

    def wrapper(doc: str) -> None:
        nonlocal vowel_count
        vowels: str = "aeiou"
        for char in doc:
            if char.lower() in vowels:
                vowel_count += 1
        print(f"Vowel count: {vowel_count}")
        func_to_decorate(doc)

    return wrapper

@vowel_counter
def process_doc(doc: str) -> None:
    print(f"Document: {doc}")

process_doc("What")
# Vowel count: 1
# Document: What

process_doc("A wonderful")
# Vowel count: 5
# Document: A wonderful

process_doc("world")
# Vowel count: 6
# Document: world
```

The `@vowel_counter` line is "decorating" the `process_doc` function with the `vowel_counter` function. `vowel_counter` is called once when `process_doc` is defined with `@` syntax, but the wrapper function that it returns is called every time `process_doc` is called. That's why `vowel_count` is preserved and printed after each time.

## It's Just a Syntactic Sugar
python decorators are just another (sometimes simpler) way of writing a higer-order function.
These two pieces of code are identical

### With Decorator

```python
@vowel_counter
def process_doc(doc: str) -> None:
    print(f"Document: " {doc})

process_doc("Sothing wicked this way comes")
```

### Without Decorator

```python
def process_doc(doc: str) -> None:
    print(f"Document: " {doc})

process_doc = vowel_counter(process_doc)
process_doc("Sothing wicked this way comes")
```
