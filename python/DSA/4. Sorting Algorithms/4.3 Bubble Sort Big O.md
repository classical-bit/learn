# Bubble Sort Big O
Implementation reference:

```python
def bubble_sort(nums: list[int]) -> list[int]:
    swapping = True
    end = len(nums)
    while swapping:
        swapping = False
        for i in range(1, end):
            nums[i - 1], nums[i] = nums[i], nums[i - 1]
            swapping = True
        end -= 1
    return nums
```

## Best and Worst Case
Sometimes it's useful to know how the algorithm will perform based on what the input data is instead of just how much data there is. In the case of bubble sort (and many other algorithms), the best and worst case scenarios can actually change the time complexity.

- Best case: If the data is pre-sorted, bubble sort becomes really fast. Can you see why? An optimized implementation of bubble sort uses a boolean flag (often called `swapped`) to track whether any adjacent elements were swapped during a pass through the array.
- Worst case: If the data is in reverse order, bubble sort becomes really slow (but still in the same complexity class as random data). Can you see why? When the data is completely in reverse order, bubble sort hits its worst-case scenario, requiring the maximum possible number of comparision and swaps. While its overall time complexity remains in the same class as random data - `O(n^2)` - the actual work done is roughly __double__ of an average/random array.
