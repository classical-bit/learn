# Constants Don't Matter
Big-O notation only describesthe theoretical growth rate of algorithms. It doesn't deal with the actual time an algorithm takes to run on a given machine. As such, when doing Big O analysis, we don't let ourselves get bogged down in details.

For example, take a look at the following functions:

```python
def print_names_once(names: list[str]) -> None:
    for name in names:
        print(name)

def print_names_twice(names: list[str]) -> None:
    for name in names:
        print(name)
    for name in names:
        print(name)
```

As would expect, `print_name_once` will take half time to run as `print_name_twice`. And in the real world of software engineering, doubling the speed is awesome. The funny thing about Big O analysis is that we don't care. We're academics.

Both of the functions above have the same reate of growth, `O(n)`. Your might be tempted to say, "`print_name_twice` should be `O(2 * n)`" but you be missing the whole point of Big O.

Constants affect actual runtime, but in Big O analysis we drop them because they don't affect how the runtime scales.

- `O(n + 3)` -> `O(n)`
- `O(2 * 3)` -> `O(n)`
- `O(10 * n^2)` -> `O(n^2)`
