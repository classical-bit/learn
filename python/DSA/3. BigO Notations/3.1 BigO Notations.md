# Big O Notations
There are a lot of existing algorithms; some are fast and some are slow. Some use lots of memory. It can be hard to decide which algorithm is the best to solve a particular problem.

"Big O" analysis is one way to compare the particularity of algorithms by classifying their time complexity.

> Big O is a characterization of algorithms according to their worst-case growth rates

We write B-O notation like this:

```
O(formula)
```

Where `formula` describes how an algorithm's run time or space requirements grow __as the input size grows__.

- `O(1)` - constant
- `O(log n)` - logarithmic
- `O(n)` - linear
- `O(n^2)` - quadratic/squared
- `O(2^n)` - exponential
- `O(n!)` - factorial

As the size of inputs grows, the algorithms become slower to complete (take longer to run). The rate at which they become slower is defined by their Big O category.

For example, `O(n)` algorithms slow down more slowly than `O(n^2)` algorithms.

## The Worst Big-O Category?
The algorithms that slow down the fastest in our chart are the factorial and exponential algorithms, or `O(n!)`, and `O(2^n)`.
